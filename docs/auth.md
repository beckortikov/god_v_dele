# Вход и доступ

## Как это устроено

1. **Вход** (`POST /api/auth/login`) проверяет логин и пароль. Пароли хранятся хешем (`scrypt`, `lib/password.ts`); старые пароли открытым текстом принимаются и при первом входе заменяются хешем.
2. При успешном входе сервер выдаёт cookie `gvd_session`: подписанная, `HttpOnly`, `SameSite=Lax`, `Secure` в продакшене, действует 30 дней (`lib/session.ts`). Браузер хранит свою копию пользователя в `localStorage` только для отрисовки интерфейса, сервер ей не верит.
3. **Каждый запрос к `/api/*`** сначала проходит через `proxy.ts`: нужна действующая сессия и роль, которой маршрут открыт (`lib/auth-policy.ts`). Иначе ответ 401 (не вошёл) или 403 (нет прав), маршрут не вызывается.
4. Проверки, которым нужно тело запроса или строка из базы («эта задача принадлежит мне», «это моё колесо»), делаются в самих маршрутах через `lib/api-auth.ts`.
5. Кто изменил запись в журнале изменений берётся из сессии, а не из заголовков запроса.
6. **Выход** (`POST /api/auth/logout`) стирает cookie. Если сервер отвечает 401, интерфейс сам возвращает на экран входа (`lib/client-actor.ts`).

## Как добавить новый маршрут

Не перечисленный в `lib/auth-policy.ts` маршрут **доступен только администратору**. Чтобы открыть его другим ролям, добавьте правило в `RULES`: префикс, роли для чтения (GET) и для записи, при необходимости область «только свои данные». Затем добавьте проверки в `tests/auth-policy.test.ts`. Публичными остаются только `/api/auth/login`, `/api/auth/logout` и `/api/telegram/webhook` (он сам проверяет секрет Telegram).

## Настройка

Ничего настраивать не нужно: ключ подписи берётся из `SUPABASE_SERVICE_ROLE_KEY`. Чтобы задать свой, укажите `SESSION_SECRET` (не короче 16 символов). Смена ключа выкинет всех из системы.

Cookie помечена `Secure`, поэтому в продакшене приложение должно открываться по HTTPS (на `localhost` по http это тоже работает).

## Ограничения

- Роль и привязки зашиты в сессию на 30 дней: если пользователя удалить или сменить ему роль, это вступит в силу при следующем входе. Чтобы закрыть доступ сразу, смените `SESSION_SECRET`.
- Защита от подбора пароля (5 неверных попыток на логин и адрес за 15 минут) хранится в памяти процесса, на нескольких серверах считается отдельно.
- Менеджер колёс по-прежнему может менять участников и их платежи (так работает его страница «Участники»).
